# Public reader onboarding review

The walkthrough used a fresh Chromium profile at desktop and 320 px phone widths, the packaged reader, a simulated inbox and neutral practice stories. Worker integration tests separately exercised SQLite account, session and feedback data and checked the signed SES request. The live inbox, Cloudflare cutover and physical pairing are separate release checks in the [activation checklist](../deploy/cloudflare/public-reader.md).

| Step | What the user sees | Friction to address |
| --- | --- | --- |
| First visit | The guest reader opens immediately. Sign in is available in the header, and the simulator can run without an account. | The editor dominates the first screen. Put **Try a practice story** and **Connect my Lovense** above the editor on a fresh visit, then collapse that introduction once the reader has used it. |
| Sign in or create an account | The same email form handles both. The code screen explains expiry and resend. A wrong code leaves the person in the same flow. | On a phone, going to the inbox can take people out of the reader. Show the destination address on the code screen and test one-time-code paste, autofill, resend and return on iOS and Android with real mail. |
| Pair a toy | **Toy setup** lets the person select a model and choose simulator or physical connection. Sign-in returns them to their selected toy, where they start pairing explicitly. | Pairing instructions should separate two-screen QR setup from same-phone setup before the code appears. If Lovense Remote cannot pair from the same phone, tell the reader immediately to open SatinLore on a second screen. Preserve the selected model and give a retry for an expired code or missing device. |
| Test and begin reading | The user selects the detected toy, checks its movements and confirms Start. A fixed-level practice story explains why the model cannot change and links to one that supports both models. | Keep a compact checklist for the current movement and a visible Stop. After setup, offer **Try a practice story** or **Open my story** with one tap. Label Nocturne’s button **Analyse with Nocturne** and keep the short data disclosure next to it. |
| Send feedback | **Feedback** opens a separate tab, so the reading position is preserved. A submitted note has a visible review status, and users can download or delete their notes. | On small screens the header uses an icon. Add a labeled **Report a connection problem** action to the failure state, with an optional preview of the model and setup step the person chooses to attach. Guest feedback currently requires sign-in, so publish a support route for someone blocked before sign-in. |

Measure the time from opening setup to the first successful movement check, the number of QR retries, and the share of connected readers who reach Start. Count simulator and physical sessions separately. Keep measurements limited to setup steps and outcomes so private stories and feedback text stay out of the funnel data.
